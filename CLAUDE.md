# Blacksmith SE Demo Base

Demo factory for Blacksmith SE demos. Design doc:
`/Users/jacobbuckles/Documents/SE/vault/5 - Projects/SE Demo/SE Demo.md`.
SE workflow and talk track: `DEMO_RUNBOOK.md`.

GitHub repo: https://github.com/jacob-buckles-org/blacksmith-se-demo-base

## Shape of the repo

- `main` = the mock customer app "Anvil Analytics" (React/TS dashboard,
  Go API, Postgres) with deliberately slow, cache-free CI on
  `ubuntu-latest`. Everything on main except the SE-facing files must
  read as a plausible customer codebase — stay in-character.
- `feature/*` branches = one Blacksmith feature each, **exactly one
  commit ahead of main**. `provision.yml` cherry-picks that commit into
  each demo repo and fails if a branch drifts to ≠1 commits. After
  changing main: `git rebase main feature/X`, squash, force-push.
- Feature commit messages are customer-visible (subject → draft PR
  title, body → PR body).
- SE-facing files scrubbed from demo repos at provision: `CLAUDE.md`,
  `DEMO_RUNBOOK.md`, `.github/workflows/provision.yml`,
  `.github/workflows/teardown.yml`. Adding a new SE-only file? Add it to
  the scrub list in provision.yml.

## Invariants to preserve

- "Before" CI must stay slow *authentically*: no sleeps. The timing knob
  is `ANVIL_WORKLOAD` (env in `ci.yml`/`test.yml`) driving CPU-bound
  test sweeps — real work that faster runners genuinely speed up.
- `backend/internal/events/` is generated: edit `backend/tools/genevents`
  and re-run `go run ./tools/genevents` (CI diffs it).
- `data/*.csv` are generated by `node data/generate.mjs` (deterministic).
- `useblacksmith/cache` and `useblacksmith/setup-*` are ARCHIVED — the
  dependency-caching branch deliberately uses standard `actions/cache` /
  `setup-node`/`setup-go`, which Blacksmith accelerates transparently.
  Don't "fix" it to use Blacksmith forks.
- Demo repos are tagged with the `blacksmith-demo` topic (teardown
  discovers them by it).
